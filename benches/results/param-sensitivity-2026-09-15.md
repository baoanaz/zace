## 0. 一句话结论

**对方建议的"去调 top20 seeds / graph 30 / ×25 / floor 0.40 / file 25% / tier3 30% / docs 10%"不可行：
其中 4 类参数在当前测试集上敏感度恰好为 `0.0000`——调它们是在拟合噪声。**

真正有信号的是**已有决策的正确性**：把 rerank 语义特征、测试抑制、基准分缩放、Repair 各自关掉，
MRR 会**显著变差**（-0.011 ~ -0.033）。即"该定的已经定对了"，当前瓶颈不在参数值。

## 1. 为什么要做这次扫描

Module/02 §7 与 R29/R30 都写着"`rerank` 分值 / 配额需 benchmark 校准"，但**从未有脚本回答过一个前置问题**：
这些参数在当前测试集上**到底有没有信号**？如果没有，任何"调参"都是在噪声里找规律——
93 条人工题上改一条用例的排名就能移动 MRR 约 0.002。

## 2. 方法（含一个必须记住的坑）

```bash
set -a; source ~/.config/zace/benchmark.env; set +a; export no_proxy='*'
uv run python benches/param_sweep.py            # 全量；--axis <名> 跑单轴；--verify 只校准
```

- **embedding 只算一次**（真实调用），之后每个配置用离线重算——参数改动不影响召回，无需重跑 embedding；
- 命中判定复用 `zace_core.cli.eval`，指标与 `benches/run.py` **逐位一致**；
- 脚本自带两道自检：① 基线必须等于官方四靶场合并值 `(0.892, 0.925, 0.6844, n=93)`，不符即报错退出；
  ② 同一配置连跑两次必须**逐位一致**。

四靶场逐仓原始证据：`benches/results/raw-task109-{cockpit-agents-py,leveldb-v1,helloagents-v1,langchain-v1}.md`。

### 坑：检索链会就地改写候选对象（勿删此节）

第一版扫描跑出"**每个**参数改动都恰好 `-0.004`"——过度整齐的结果让我起疑，查下去发现：

| 观测 | 值 |
|---|---|
| 一批候选进 `assemble` 前 `reasons` 条数 | 262 |
| 同一批候选出来后的 `reasons` 条数 | **389** |
| 同一批对象第二次跑 `used_tokens` | 5841 → **5830** |

`expand` / `rerank` / `assemble` 会**就地追加 `reasons`、覆盖 `score`**。因此任何
"预计算召回 → 反复变下游参数"的 ablation，**从第二组配置起就在测被污染的对象**。
症状极隐蔽（数字看着完全正常，且"每项都微小变差"很像保守结论）。

**修法**：每题 `copy.deepcopy` 干净候选后重算（`param_sweep.py` 已实现，并有确定性自检兜底）。
`benches/ratio_bench.py` 不受影响——它每个参数值都重新跑 `search_with_retrieval`，召回侧产新对象。

## 3. 结果（93 条正例，基线 R@5 0.892 / R@10 0.925 / MRR 0.6844）

判读纪律：**|ΔMRR| < 0.005 视为噪声**（<1 条用例的排名变化）。

### 3-1 敏感度为 0.0000 —— 现在不该调

| 参数 | 取值对比 | ΔMRR | 判定 |
|---|---|---|---|
| `seeds`（图扩展种子数） | 10 / **20** / 40 | **+0.0000** | 完全无影响 |
| `max_expanded`（扩展总量） | 15 / **30** / 60 | **+0.0000** | 完全无影响 |
| `tier3_ratio` | **0.30** / 0.45 | **+0.0000** | 完全无影响 |
| `single_file_ratio` | **0.25** / 0.40 | **+0.0000** | 完全无影响 |

这 4 个是对方点名要调的多数。**它们的取值在当前测试集上不影响任何结果**——
两种可能：① 确实不重要（那应**删掉旋钮**而非调它）；② 当前题目没覆盖到生效区（那要先有更好的题）。
**两种结论都要求先有更好的测试集**，而不是现在动参数。

### 3-2 反向验证：这些决策是对的（关掉显著变差）

| 决策 | 关掉/改坏后 | ΔMRR | 出处 |
|---|---|---|---|
| 向量语义特征 `vector_rank_top=1.5` | 设 0（关闭） | **−0.0334** | TASK-105 |
| 测试夹具抑制 `test_fixture=−1.5` | 设 0（不抑制） | **−0.0182** | TASK-108 |
| 基准分缩放 `RRF_BASE_SCALE=25` | ×100 | **−0.0209** | TASK-105 |
| 同上 | ×50 / ×10 | −0.0076 / −0.0090 | TASK-105 |
| **Repair 回路（Gap 补检）** | 关闭 | **−0.0109** | TASK-109 |

**这是本次扫描最有价值的部分**：过去几轮的四个判断（语义特征、测试抑制、缩放定档、补检）
都被独立复现为"确实有效"。`×25` 尤其值得注意——×10/×50/×100 全部变差，说明 TASK-105 那次定档不是拟合。

### 3-3 噪声内：方向上对，但幅度不支撑改动

| 参数 | 取值 | ΔMRR | 说明 |
|---|---|---|---|
| `score_ratio` | 0.40 → **0.15** | +0.0021 | 与 TASK-108（0.50→0.40）同向 |
| `docs_ratio` | 0.10 → **0.05** | +0.0035 | 同上 |

两者都是"继续放宽"的小幅正收益，但**远在噪声内**（+0.002~0.004 vs 阈值 0.005）。
**不足以支撑解冻 R29/R30**——需要 TASK-093 的真实数据。

### 3-4 反向：这些方向明确变差

| 参数 | 取值 | ΔMRR |
|---|---|---|
| `score_ratio` | 0.40 → 0.55 | −0.0067 |
| `docs_ratio` | 0.10 → 0.20 | −0.0062 |

说明当前值已在合理侧；继续收紧是唯一微正方向，但幅度不够。

## 4. Repair 的定位与代价（供文档命名参考）

架构表达建议采用：**Recall → Expand → Rank → Pack → Repair**，其中 Repair 是
**单次 Evidence Repair Loop**（受限反馈回路），**不是第五级排序**。实测证据：

| 观测（93 条正例） | 值 |
|---|---|
| Gap 触发 | 75/93（**80%**） |
| 其中 coverage 有提升 | **8 条** |
| 有开销无 coverage 提升 | **67 条** |
| 纯开销 token | 81127 |
| 有收益用例 token | 12760 |
| **开销 / 收益比** | **约 6.4×** |

一个"收益 8 条、开销 67 条、但在整体指标上净正（关掉 −0.0109）"的机制，
**结构上只能是回路，不可能是主链路的一级**。

**Repair 的三条不变量**（实测成立，建议写进设计文档）：
1. **只提池内候选**——93 条 / 455 个补检候选，**零违反**；
2. 不新增召回通道、不改排序键；
3. 独立小预算，不挤占首轮份额。

> 触发面偏宽（80% 触发 vs 8.6% 收益）是已知问题。实测四种候选闸门
> （仅 `answerable=false` / `truncated` / 首轮无命中 / 组合）**都会丢掉大部分收益**
> （丢 2–6 条 / 共 8 条），因此**现在不该硬收**，先要更好的测试集。

## 5. 对下一步的建议（按性价比）

1. **不要现在调参**——4 类参数敏感度为 0，其余在噪声内。**先做 TASK-093 的真实数据闭环**。
2. **可以删的旋钮**：`seeds` / `max_expanded` / `tier3_ratio` / `single_file_ratio` 若在真实数据上
   仍无区分度，应作为配置项删除（少一个可调参数 = 少一处拟合风险），而不是留着被误调。
3. **候选验证**：`score_ratio`、`docs_ratio` 的收紧方向（0.15 / 0.05）在真实数据上值得复测。
4. **基础设施**：§2 的就地改写污染建议单独开卡（影响任何复用候选对象的调用方）。
