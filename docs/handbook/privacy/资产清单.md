# 隐私资产清单（部署前第一步）

> **读者**：要在新机器（WSL / VPS）部署 zace 的人。
> **目标**：把**不能进 git** 的东西一次性摆到位，然后按
> [`../deployment/vps.md`](../deployment/vps.md) 或 [`../deployment/wsl-live.md`](../deployment/wsl-live.md) 启动服务。
>
> 一句话流程：**干净代码（GitHub） + 隐私包（本文档） → 跑起生产环境**。

## 1. 为什么需要这份文档

zace 的**代码**全部在 GitHub 上，`git clone` 即可。但有四类东西**永远不进仓库**：

1. API key / token（embedding、LLM、npm）；
2. 环境变量文件（含 key 明文）；
3. 机器相关的部署配置（systemd unit、nginx 站点）；
4. 持久数据（索引、账户库）。

它们散落在**仓库外**的多个位置。换机器时逐个重配容易漏、容易错，
所以统一收进一个**隐私包**：拷过去 → 跑一次 `restore.sh` → 完事。

## 2. 资产清单（权威表）

| # | 资产 | 本机位置 | 权限 | 含密 | 用途 |
|---|---|---|---|---|---|
| 1 | 本地开发 env | `zace/.env` | **600** | ✅ | 本机跑 core / 索引时的 embedding + LLM key |
| 2 | live 环境 env | `~/.config/zace/live.env` | 600 | ✅ | WSL 接入验证环境（systemd 读它） |
| 3 | benchmark env | `~/.config/zace/benchmark.env` | 600 | ✅ | 跑跨仓库基准（§3 环境） |
| 4 | npm token | `~/.npmrc` | 600 | ✅ | 发布 `zace-client` 到 npm |
| 5 | systemd unit | `/etc/systemd/system/*.service` | 644 | ❌ | 服务启动定义 |
| 6 | nginx 站点 | `/etc/nginx/sites-available/*` | 644 | ❌ | 路由定义（80 → 8787） |
| 7 | 持久数据 | `~/.zace/live`、`~/.zace/bench/...` | 700 | 含业务数据 | 索引 + 账户库（**体积大，默认不进包**） |

> **权限要求**：1-4 必须 `0600`。`zace/.env` 此前是 644（同机其他用户可读）——
> **如果你的是 644，立刻改**：`chmod 600 zace/.env`。

## 3. 密钥的种类与从哪拿

| 用途 | 变量 | 从哪里获取 | 备注 |
|---|---|---|---|
| embedding（主路径） | `EMBED_API_KEY` | [Voyage](https://www.voyageai.com/) → API Keys | `voyage-4-lite`，有免费额度 |
| embedding（备选） | `EMBED_API_KEY` | [硅基流动](https://cloud.siliconflow.cn/) → API 密钥 | `bge-m3`，免费但 TPM 仅 50 万 |
| LLM 总结（`ask_project`） | `ANSWER_API_KEY` | 自建 OpenAI-compatible 网关 | 不配则 `ask` 返回"总结模型不可用"，检索仍可用 |
| npm 发布 | `~/.npmrc` 的 `_authToken` | `npm login` 后自动写入 | 只在要发版时用 |

**没有码也能跑**：不配 `ANSWER_*` 时 `search_context` 完全可用，只是 `ask_project` 会诚实报"证据不足/模型不可用"。

## 4. 隐私包内容与结构

用一个目录装齐，结构如下：

```text
zace-secrets/
├── README.md              # 快速说明（同本文件精简版）
├── MANIFEST.md            # 逐文件说明 + 恢复顺序 + 轮转指引
├── restore.sh             # 一键恢复（交互式，支持 wsl / vps 两种模式）
├── env/
│   ├── project.env        # → zace/.env
│   ├── live.env           # → ~/.config/zace/live.env
│   └── benchmark.env      # → ~/.config/zace/benchmark.env
├── npm/
│   └── npmrc              # → ~/.npmrc
├── systemd/
│   ├── zace-live.service  # WSL 接入验证（按需启停）
│   └── zace-service.service  # VPS 生产
└── nginx/
    ├── zace-wsl.conf      # → sites-available/zace-live
    └── zace-vps.conf      # → sites-available/zace
```

**生成方式**：在本机跑

```bash
bash scripts/pack-secrets.sh          # 产出 ~/zace-secrets.tar.gz
```

脚本会：收集上表 #1-#6 → 打码检查（拒绝把明显不是密钥的文件塞进来）→ 打 tar.gz（`0600`）。

**恢复方式**（新机器）：

```bash
tar xzf zace-secrets.tar.gz -C ~/
bash ~/zace-secrets/restore.sh wsl     # 或 vps
```

`restore.sh` 做的事：
1. 交互式确认目标路径与用户名（模板里的 `<USER>` 要替换）；
2. 写文件 + `chmod 600`；
3. 打印"下一步该做什么"（按模式给不同指引）。

## 5. 恢复顺序（务必按序）

```text
① 代码      git clone https://github.com/baoanaz/zace.git
② 依赖      uv sync（Python 3.12+）
③ 隐私包    本文档 §4
④ 部署配置  systemd + nginx（隐私包里已带模板）
⑤ 启动      systemctl start
⑥ 初始化    bootstrap 建账户 + 建 API Key
⑦ 验证      healthz / api/meta / 前端 200
```

对应命令在 [`../deployment/wsl-live.md`](../deployment/wsl-live.md) §2 与
[`../deployment/vps.md`](../deployment/vps.md) §2。

## 6. 什么不进包

| 东西 | 为什么不进 | 怎么获得 |
|---|---|---|
| 基准索引 `~/.zace/bench/...` | 体积大（254 MB+），且含内部源码派生数据 | 重建（`zace-core ingest --full`）或 `scripts/bench-bundle.sh` 单独传 |
| 持久数据 `~/.zace/live` | 含业务数据与账户库 | 从旧机 `tar` 备份，或全新初始化 |
| 任何 `*.pem` / `*.key` | 本机当前无此类资产 | 若将来有，单独管理 |
| 仓库代码 | 本就公开 | `git clone` |

## 7. 安全纪律

- **绝不提交**：`.gitignore` 已排除 `.env` / `.env.*` / `.zace/`，但**不要依赖它**——
  提交前用 `git status` 自查。
- **不进聊天/日志**：key 不要贴进 issue、PR、AI 对话。本仓库历史已核查**干净**
  （只提交过 `.env.example`）。
- **权限**：所有含密文件 `0600`，配置目录 `0700`。
- **换机器后轮转**：如果 key 曾以明文经过不可信通道（聊天、截图、公共终端），
  **视为已泄露，去各自控制台重新签发**（见 §8）。

## 8. 密钥轮转指引

| 密钥 | 轮转步骤 | 影响 |
|---|---|---|
| `EMBED_API_KEY`（Voyage） | 控制台重新签发 → 更新 env → 重启服务 | **不影响索引**（向量已生成，不需要重嵌） |
| `ANSWER_API_KEY`（网关） | 网关侧重新签发 → 更新 env → 重启 | 无 |
| npm token | `npm token revoke <token>` → `npm login` | 旧 token 立即失效 |

> `EMBED_API_KEY` 轮转**不触发重嵌**：向量对账看的是模型/维度指纹，不是 key。
